## 1. 设计愿景与原则

### 1.1 一句话愿景

**像握住一块温润的玻璃来看清知识**——界面通透、精致、安静，让内容成为主角，让交互有温度但不喧哗。

### 1.2 五条设计原则

| 原则 | 含义 |
|---|---|
| **克制即高级** | 高级感来自留白、层级、克制的特效，不是特效堆叠 |
| **玻璃服务内容** | 玻璃让文字更清晰、层级更分明才用；让文字发虚、满屏发光就是 AI 味 |
| **统一设计语言** | 颜色、字体、间距、圆角、图标、动效全项目一致 |
| **反馈有意义** | 动画只在操作时出现（金币滚动、按钮按压、页面切换），不为动而动 |
| **三态完整** | 每个列表/页面都有加载态、错误态、空态 |

## 2. 关键认知：什么叫"去 AI 味"的液态玻璃

### 2.1 高级感 vs AI 味对照表（判断标准）

| 维度 | ❌ AI 味（要避免） | ✅ 高级感（要追求） |
|---|---|---|
| 背景 | 紫蓝粉大渐变 + 光晕，整页发光 | 低饱和暖灰/米白打底 + 一处柔和晕染 + 极细颗粒质感 |
| 玻璃用法 | 每个方块都糊一层，整页发虚 | **只用在浮层**：导航栏、弹窗、悬浮卡片；主体背景保持"实" |
| 边缘 | 彩色发光渐变边框 | 1px 半透明白描边（模拟玻璃反光）+ 极淡投影 |
| 模糊值 | 拉满到看不清 | 克制在 12–24px，文字始终清晰 |
| 动效 | 无意义悬浮、旋转、呼吸、扫描线 | 只在操作时反馈：数字滚动、按压、切换 |
| 字体 | 默认字体、层级不清 | 有个性、标题正文拉开字重和字号 |
| 信息密度 | 塞满特效、全是占位内容 | 大量留白、1 个强调色、清晰层级 |

> **唯一判断标准**：特效是否服务于内容。让内容更清楚 = 漂亮；让内容更花哨 = AI 味。

### 2.2 液态玻璃的技术构成（Apple Liquid Glass 风格）

真正的液态玻璃由这几样构成，**核心全是 CSS**：

1. **背景模糊**：`backdrop-filter: blur()` 让玻璃背后的内容虚化；
2. **半透明底色**：`background: rgba(...)` 透出背景色；
3. **边缘高光**：1px 半透明白描边，模拟玻璃反光；
4. **层次阴影**：柔和的多层阴影营造厚度；
5. **随交互变化的光泽**（可选、克制）：悬停时高光轻微移动。

## 3. 色彩系统

### 3.1 设计变量（CSS 变量，深浅两套）

采用语义化变量（不是直接写色值），Tailwind 映射这些变量，主题切换只换变量值。

| 语义变量 | 用途 | 浅色主题（建议基调） | 深色主题（建议基调） |
|---|---|---|---|
| `--bg` | 页面底色 | 暖灰/米白（低饱和） | 深墨灰（非纯黑） |
| `--surface` | 卡片/玻璃底 | 半透明白 | 半透明浅灰 |
| `--text-primary` | 主文字 | 深灰近黑 | 近白 |
| `--text-secondary` | 次要文字 | 中灰 | 浅灰 |
| `--accent` | 强调色（唯一） | 待定（建议低饱和青/靛） | 同色系略提亮 |
| `--glass-border` | 玻璃描边 | `rgba(255,255,255,.6)` | `rgba(255,255,255,.15)` |
| `--glass-shadow` | 玻璃阴影 | 柔和淡影 | 稍深柔影 |
| `--success` | 正确/答对 | 克制绿（中国市场注意：非涨红语义） | 同色系 |
| `--error` | 错误/答错 | 柔和红 | 同色系 |
| `--coin` | 金币 | 暖金黄 | 暖金黄（略降饱和） |

> 建议只用**一个**强调色贯穿全站，避免多色乱炖。

### 3.2 色彩使用规则

1. 主背景低饱和，让强调色成为唯一亮点；
2. 金色只用于金币，绿色只用于正确，红色只用于错误——语义专一；
3. 玻璃底色透明度克制，保证文字对比度；
4. 避免大面积高饱和色块。

### 3.3 可访问性对比度

- 正文文字与背景对比度 ≥ 4.5:1（WCAG AA）；
- 大标题 ≥ 3:1；
- 玻璃上的文字必须在深浅两套主题下都达标。

## 4. 字体系统

| 层级 | 用途 | 字重 | 建议字号 |
|---|---|---|---|
| H1 | 页面主标题 | 600–700 | 28–32px |
| H2 | 区块标题 | 600 | 20–24px |
| H3 | 卡片标题 | 600 | 16–18px |
| Body | 正文/题干 | 400 | 15–16px |
| Caption | 辅助说明 | 400 | 12–13px |
| Code | 代码 | 500（等宽） | 14px |

**规则**：
- 中文优先系统中文字体栈，英文可搭配有个性的无衬线体；
- 题干字号不小于 15px，保证长时间阅读舒适；
- 标题与正文拉开字重/字号差，建立清晰层级；
- 代码用等宽字体（CodeMirror 默认处理）。

## 5. 间距、圆角与图标

### 5.1 间距系统（基于 4px 网格）

| 令牌 | 数值 | 用途 |
|---|---|---|
| space-1 | 4px | 图标与文字微间距 |
| space-2 | 8px | 紧凑元素间距 |
| space-3 | 12px | 小组件内边距 |
| space-4 | 16px | 常规间距 |
| space-6 | 24px | 区块间距 |
| space-8 | 32px | 大区块/页面边距 |
| space-12 | 48px | 页面大留白 |

> 大量留白是高级感的关键。宁可疏朗，不要拥挤。

### 5.2 圆角系统

| 元素 | 圆角 |
|---|---|
| 按钮/标签 | 8–10px |
| 卡片/玻璃面板 | 16–20px |
| 弹窗 | 20–24px |
| 头像/圆形图标 | 50% |
| 胶囊标签 | 999px |

> 全项目圆角风格统一，不要方的方的、圆的圆。

### 5.3 图标

- 统一使用 **Lucide React**，线性风格、`stroke-width` 一致；
- 图标尺寸成体系（16/20/24px）；
- 图标必须配可读文字或 `aria-label`，不单独用图标表达关键含义。

## 6. 玻璃效果规范（手写 CSS）

### 6.1 标准玻璃配方（基准值，按主题微调）

```css
.glass {
  background: var(--surface);                 /* 半透明底色 */
  backdrop-filter: blur(16px) saturate(140%); /* 模糊 + 轻微提饱和 */
  -webkit-backdrop-filter: blur(16px) saturate(140%);
  border: 1px solid var(--glass-border);      /* 半透明白描边 = 反光 */
  box-shadow: 0 8px 32px var(--glass-shadow); /* 柔和层次阴影 */
  border-radius: 18px;
}
```

### 6.2 参数使用规范

| 参数 | 范围 | 规则 |
|---|---|---|
| 模糊值 `blur` | 12–24px | 导航栏/弹窗 12–16px；悬浮卡片可到 24px；不得超过 24px |
| 底色透明度 | 0.5–0.75 | 深色主题可更低，浅色主题偏高，保证文字清晰 |
| 描边 | 1px 半透明 | 浅色用高透白，深色用低透白 |
| 阴影 | 柔和、低不透明 | 不用硬阴影、不用彩色发光 |

### 6.3 玻璃使用位置（重要）

**✅ 用玻璃**：
- 顶部/底部导航栏；
- 弹窗、抽屉、提示浮层；
- 悬浮态卡片、金币结算浮层；
- 书城详情浮层。

**❌ 不用玻璃**：
- 页面主背景（保持"实"，否则整页发虚）；
- 大段正文区域（影响阅读）；
- 大量小元素逐个加玻璃（性能与视觉双输）。

> 记住：玻璃是"浮在内容之上的一层"，不是"包裹一切的外壳"。

### 6.4 性能约束

- `backdrop-filter` 只用于浮层，单屏玻璃元素控制在少数几个；
- 移动端适当降低模糊值；
- 尊重系统"减少动态效果"偏好（`prefers-reduced-motion`），关闭非必要光泽动画。

### 6.5 液态玻璃胶囊控件（v1.3 新增）

高频交互控件（图标按钮、分段切换、主题切换、主按钮）采用「胶囊玻璃」手感，是标准玻璃配方在交互控件上的延伸，不是新材质：

| 要素 | 规格 |
|---|---|
| 形状 | 全圆角胶囊 `border-radius: 999px`（符合 5.2 节既有「胶囊标签」项） |
| 底与折射 | 玻璃底 + `blur(18px) saturate(155%)`；移动端降到 14px |
| 高光 | 顶部一条内阴影高光弧；另有跟随鼠标的柔光点（`--glow-x/--glow-y`，默认顶部），浅色用白、深色低透明 |
| 悬停 | 上浮 2–3px + 轻微放大，阴影加青碧色氛围（仍非彩色发光边框） |
| 按下 | 弹性曲线 `cubic-bezier(.34, 1.56, .64, 1)` 收缩回弹，带轻微过冲 |
| 焦点 | 键盘 `focus-visible` 用 2px 描边，不套方角 ring；禁用态不回弹 |
| 减少动态 | `prefers-reduced-motion` 下取消位移与回弹，仅保留颜色反馈 |

**实现落点**：样式在 `src/styles/glass.css` 的 `.glass-pill` 系列，变量在 `globals.css` 三套主题中各有一份；鼠标跟随由 `src/lib/use-glow.ts` 写入 CSS 变量。组件侧只需组合类名，不内联视觉参数。

**嵌套约束**：已内含玻璃底的容器（如侧栏、底栏）内部导航项用 `.glass-pill--light` 轻量变体——去掉 `backdrop-filter`，只保留圆角、高光与回弹，避免模糊叠加导致性能与视觉双输。

## 7. 组件规范

### 7.1 通用组件（components/ui）

基于 shadcn/ui（源码进仓库），统一改造为玻璃风格：Button、Card、Dialog、Tabs、Progress、Badge、Tooltip、Switch、Skeleton。

**组件状态完整性要求**：每个交互组件必须实现以下状态：

| 状态 | 要求 |
|---|---|
| 默认 | 清晰可点/可读 |
| 悬停（hover） | 轻微反馈（高光/位移 1–2px） |
| 按下（active） | 按压反馈（缩放 0.98） |
| 聚焦（focus） | 清晰焦点环（键盘可访问） |
| 禁用（disabled） | 降低透明度、不可点 |
| 加载（loading） | 骨架屏或 spinner |

### 7.2 关键业务组件

| 组件 | 视觉要点 | 交互反馈 |
|---|---|---|
| 题目卡（QuestionCard） | 玻璃卡片，题干清晰，字号 ≥15px | 选中选项高亮 + 轻微按压 |
| 答案切换器（AnswerPanel） | Tabs 切"专业版/大白话版"，默认大白话 | 切换有淡入过渡 |
| 金币徽章（CoinBadge） | 暖金图标 + 数字 | 获得金币时数字滚动动画 |
| 任务进度环（DailyTaskRing） | 环形进度，中心显示 x/y | 完成瞬间光晕（唯一允许的点睛效果候选） |
| 代码编辑器（CodeEditor） | CodeMirror，主题随深浅切换 | 运行按钮反馈、结果区清晰 |
| 解锁弹窗（UnlockDialog） | 玻璃浮层，价格醒目 | 金币不足时按钮禁用 + 差额提示 |
| 书籍卡片（BookCard） | 小册子/外部书样式区分，许可徽章 | 悬停轻微上浮 |

## 8. 动效规范

### 8.1 原则：只为有意义的服务

**允许的动效**：
- 金币获得：数字滚动（约 400ms）；
- 按钮按压：缩放 0.98（约 100ms）；
- 页面/答案切换：淡入（约 200ms）；
- 任务完成：一次性的、克制的庆祝反馈。

**禁止的动效**：
- 无意义的持续悬浮、旋转、呼吸；
- 扫描线、粒子背景、打字机效果、文字闪烁；
- 满屏彩带 confetti（除非明确要求且只用一次）。

### 8.2 动效参数

| 类型 | 时长 | 缓动 |
|---|---|---|
| 微反馈（按压/高亮） | 100–150ms | ease-out |
| 过渡（淡入/切换） | 200–300ms | ease-in-out |
| 数字滚动 | 400–600ms | ease-out |

> 遵循"全站最多 1 个点睛效果件"规则（见 ADR-010）：如果要用 Magic UI 类效果，只选 1 处（建议任务完成），其余全用克制 CSS。

## 9. 布局与响应式

### 9.1 断点（Tailwind 默认）

| 断点 | 宽度 | 布局策略 |
|---|---|---|
| 手机 | < 640px | 单列，底部导航，重点保证做题体验 |
| 平板 | 640–1024px | 单列或两列，适当留白 |
| 桌面 | ≥ 1024px | 居中内容容器（最大宽度约 1200px），可侧边导航 |

### 9.2 布局规则

- 内容居中，最大宽度约束，避免超宽屏拉伸；
- 移动端优先设计（先做好手机，再扩展桌面）；
- 底部导航（手机）/ 侧边导航（桌面）；
- 安全区适配（刘海屏 padding）。

### 9.3 页面清单与布局要点

| 页面 | 布局要点 |
|---|---|
| 首页 | 今日任务进度（进度环）+ 继续学习入口 + 金币/等级概览 |
| 闯关/答题页 | 题干在上、选项/编辑器在中、答案面板在下；金币变化浮层 |
| 书城页 | 两个 Tab（我的小册子 / 外部书籍），卡片网格 |
| 个人页 | 等级、积分、成就墙、统计 |
| 设置页 | 主题（跟随/浅/深）、每日强度、清除数据（二次确认） |

## 10. 三态设计（加载 / 错误 / 空）

| 页面/区域 | 加载态 | 错误态 | 空态 |
|---|---|---|---|
| 题库列表 | 骨架卡片 | "加载失败，重试"按钮 | "还没有题目，去引导设置" |
| 书城 | 骨架卡片 | 重试 | "书城空空，先去做题赚金币" |
| 成就墙 | 骨架 | 重试 | "还没有成就，继续加油" |
| 代码判题结果（二期） | "运行中…" | "运行出错，检查代码" | — |

> 三态文案用亲切、鼓励的语气，符合产品气质，不用冷冰冰的系统提示。

---

## 11. 可访问性（A11y）

1. 语义化 HTML（`<button>`/`<nav>`/`<main>` 等）；
2. 所有交互元素键盘可达，焦点环清晰；
3. 图标按钮配 `aria-label`；
4. 对比度达标（见 3.3）；
5. 尊重 `prefers-reduced-motion`，关闭非必要动效；
6. 尊重 `prefers-color-scheme`（跟随系统主题的基础）。

## 12. 反模式清单（落地时逐条自查）

- [ ] 背景是否用了紫蓝粉大渐变 + 光晕？（❌ 改低饱和底色）
- [ ] 是否每个方块都加了玻璃？（❌ 只在浮层用）
- [ ] 模糊值是否超过 24px 导致文字发虚？（❌ 调回 12–24px）
- [ ] 是否有彩色发光渐变边框？（❌ 改 1px 半透明白描边）
- [ ] 是否有无意义的持续动画？（❌ 删除）
- [ ] 是否用了 2 个以上效果库组件？（❌ 最多留 1 个点睛）
- [ ] 强调色是否不止一个？（❌ 收敛到 1 个）
- [ ] 是否有页面缺加载/错误/空态？（❌ 补齐）
- [ ] 文案是否冷冰冰？（❌ 改亲切鼓励语气）

## 13. 与工具链的对应

| 需求 | 工具/来源 |
|---|---|
| 基础组件源码可控 | shadcn/ui（源码进仓库） |
| 玻璃设计变量参考 | glasscn（MIT，13 调色板/7 材质）/ lenscn（MIT，真实折射） |
| 非默认主题生成 | tweakcn（shadcn 主题可视化生成器）——避免默认样式的 AI 味第一步 |
| 图标 | Lucide React |
| 动效 | Motion（克制）或纯 CSS |
| 代码编辑器主题 | CodeMirror 深浅主题随系统切换 |

> 落地顺序建议：先用 tweakcn 生成一个非默认主题（去 AI 味第一步）→ 再叠加手写玻璃 → 最后用 Motion 加有意义的反馈。
